## 1. 무엇인가

- **Xetical** (c는 소문자): DesktopCal(중국산 바탕화면 달력)을 본뜬 **구글 캘린더·구글 할 일 바탕화면 달력**. Windows 전용, Python 3.13 + PySide6.
- **위치:** `D:\Dev\Projects\XetiCal`. 폴더 이름은 원래 GoogleCal이었다.
- **git:** 2026-10-21부터 git으로 관리한다. 공개 GitHub 저장소 https://github.com/0eti/Xetical (`main`).
  - 공개 전에 개인정보를 지우려고 기록을 다시 썼다. 지우기 전 기록은 비공개 저장소 `0eti/Xetical-old`에 남아 있다(사용자가 웹에서 지우면 됨).
  - 이 저장소는 공개다. 커밋하기 전에 개인정보(메일·캘린더 이름·프로젝트 번호 등)가 들어가지 않았는지 확인할 것.
  - **`git add -A` 금지:** 사용자가 프로젝트 폴더에 파일(설정 백업 등)을 둘 수 있다. 커밋은 파일을 하나씩 지정해서 한다.
    (2026-10-22 설정 백업 `Xetical-설정.json`이 실수로 올라갔다가 지워졌다. 예전 커밋 id로는 아직 열리지만 할 일 이름 하나뿐이라 사용자가 그대로 두기로 함)
  - 커밋 작성자는 저장소 로컬 설정(0eti, GitHub noreply 메일). `data/`, `.venv/`, `client_secret*.json`은 `.gitignore`로 뺐다.
  - 파일마다 줄끝이 다르다(CRLF/LF 섞임, 파일 하나 안에서는 같음). `.gitattributes`에서 `*.bat`만 CRLF로 고정.
- **실행:** `Xetical.bat` (CRLF, ASCII 전용). 처음이면 `.venv`를 만들고 `requirements.txt`를 설치한 뒤 `pythonw main.pyw`를 실행한다.
- **사용자가 원하는 방향**
  - **DesktopCal과 최대한 비슷하게.** 특히 설정 창 구성.
  - 기능을 넣을 때마다 목록 → 번호 선택 → 구현 순서로 진행해 왔다.
- **DesktopCal은 아직 설치돼 있고 자동 실행도 등록돼 있다.**
  - 위치: `%APPDATA%\DesktopCal`, DB: `Db\calendar.db`
  - 사용자는 예전 DesktopCal 데이터는 필요 없다고 했다(불러오기 안 함).

## 3. 구글 연동 상태

- 사용자 계정의 Google Cloud 프로젝트를 쓴다. OAuth 클라이언트는 데스크톱 앱 유형.
- Calendar API와 Tasks API 모두 켜져 있다.
- 동의 화면 앱 이름: Xetical
- 게시를 위해 홈페이지·개인정보처리방침 페이지를 `site/`에 만들었다.
  - GitHub Pages 계정 0eti(`0eti.github.io`)를 쓰자고 제안했다.
  - **사용자가 실제로 게시했는지는 확인하지 않았다.** 테스트 상태면 토큰이 7일마다 만료된다.
- 권한(scope): `calendar.readonly`, `calendar.events`, `tasks`. 사용자 토큰에는 tasks 권한도 있다.
- 사용자 캘린더는 기본 캘린더 외에 여러 개(숨긴 것 포함), 할 일 목록 1개. 예전 반복 할 일(`task_repeats`)은 반복 할 일 기능이 들어간 버전의 첫 동기화 때 반복 일정으로 옮겨진다.

## 4. 기능 현황

- **완성:** DesktopCal식 화면과 설정 전체, 칸 편집기, 반복·알림·카운트다운, 공휴일·음력·절기, 할 일(마감일 있는 것만, 사용자 선택 "(가)").
- **1차 기능 추가 완료(사용자 번호 기준)**
  - 1-1 칸 ☐ 체크, 1-2 오프라인 대기, 1-3 Ctrl+Z(달력을 클릭해 활성화된 상태에서만), 1-5 아이콘 클릭 통과, 1-6 막대, 1-7 끌어서 옮기기, 1-8 반복 줄 편집, 1-9 모니터 변경, 1-11 초대 응답, 1-12 로그 제한
  - 2-2 하루 상세, 2-3 아침 요약, 2-4 복사·붙여넣기, 2-6 테마
  - **트래커(2026-10-22, 사용자 요청):** 구글과 동기화하지 않는 내부 기능. 달력 창 안 아래쪽에 올해(1~12월 고정) 칸.
    모양은 주 단위(7×53)/월 단위(12×31) 선택, 오늘·지난 날만 칠함, 트래커 여러 개(설정 `mood_trackers`, 색마다 이름).
    칠한 날은 `data/moods.json`, 설정 백업에 `moods`로 들어간다. 설정 창 '트래커' 탭(5번, 계정 6·정보 7).
  - **트래커 드라이브 동기화(2026-10-22):** 설정 `mood_sync`. 드라이브 앱 전용 폴더(appDataFolder)의 `xetical-moods.json`.
    권한 `drive.appdata`는 켰을 때만 로그인에서 받는다(`GCal.want_drive`). 사용자 클라우드 프로젝트에서 Drive API를 켜야 한다.
    날마다 [색, 바꾼 시각]을 두고 지운 날도 빈 색으로 남긴다. 합치기는 `mood.merge_sync`: 칠한 날은 날짜마다 나중 것,
    트래커는 트래커마다 나중 것(트래커의 `"t"`, 설정에서 바꿀 때 `stamp_trackers`가 찍음), 지운 트래커는 설정 `mood_deleted`
    {id: 지운 시각}(LOCAL_ONLY, 백업에 안 들어감)으로 다른 PC에도 지운다. 받은 결과는 앱에서 지금 목록과 한 번 더 합친다
    (`merge_trackers`, 동기화 중에 바꾼 것 보존). 예전 `mood_trackers_t`(목록 통째로 이기기)는 다른 PC의 새 트래커를 지워서 버렸다.
    편지함 없이 동기화마다 합쳐서 올린다(오프라인이면 다음에). 설정 백업 가져오기는 `MoodData.restore`(지금 시각으로 덮어씀)이고
    가져온 트래커에도 지금 시각을 찍는다. exe에는 drive.v3.json 설명 파일도 넣는다.
    실제 드라이브 읽기·쓰기·합치기 확인(t_google 32/32, 2026-10-22). 구글 저장 공간이 가득 차면 storageQuotaExceeded(403)로

## 6. 함정과 주의 (꼭 읽기)

**파일 편집**
- `.bat`는 **CRLF + ASCII만** 쓴다. `sed -i`가 LF로 바꿔서 깨진 적이 있다.
- 파이썬 heredoc 편집에서 줄 끝 `\`(줄 이음)가 들어간 문자열은 매칭이 안 됐다. 이때는 Edit 도구를 쓰거나 스크립트를 파일로 저장해 실행한다.
- `Path.write_text`는 Windows에서 CRLF로 저장한다. 파일 줄끝이 섞여 있으니 문자열을 매칭할 때 주의한다.

**코드**
- **QDialog 속성 이름으로 `done`, `scroll` 등 Qt 메서드 이름을 쓰지 말 것.** `self.done = QCheckBox`가 닫기 기능을 덮어써서 창이 안 닫혔다. 지금은 `done_box`로 바꿨다.
- 대화상자는 **부모 없는 최상위 창**이어야 한다. 달력의 자식이 되면 바탕화면 아래에 깔린다.

**실행과 시험 환경**
- 작업하는 앱이 MSIX 패키지면, 거기서 띄운 자식 프로세스는 HKCU 레지스트리와 AppData 쓰기가 가상화된다. 그래서 **사용자처럼 실행하려면 `explorer.exe "D:\…\Xetical.bat"`로 띄운다.**
  - 자동 실행 설정도 사용자가 직접 실행한 앱에서 바꿔야 실제로 반영된다.
- 화면 시험(computer-use)에서 주의할 것
  - `pythonw.exe`는 허용 목록에 없다. 시험할 때는 `.venv\Scripts\python.exe main.pyw`를 `-WindowStyle Hidden`으로 띄운다("Python 3.13 (64-bit)" 허용). 끝나면 explorer로 bat를 다시 실행한다.
  - **`type` 도구는 클립보드로 붙여넣는다.** clipboardWrite 권한이 없을 때 **사용자 클립보드 내용이 일정으로 저장되는 사고**가 있었다(지웠다). 반드시 `write_clipboard` 다음에 `ctrl+v`를 쓰고, 저장 전에 확대해서 확인한다.
  - 클립보드에 링크가 들어가면 사용자 PC의 다운로드 관리자가 반응할 수 있다. 미리 끄게 한다.
  - 다른 창이 바탕화면을 덮고 있어서 두 번째 클릭이 그쪽으로 갔다. 시험 전에 Xetical을 활성화하고 **Win+D**를 누르면 해결된다.
  - 클릭 통과 모드에서는 도구 규칙상 탐색기 위 우클릭과 드래그를 할 수 없다. 우회하지 말 것.
- 실제 구글 시험은 정리를 반드시 `finally`에서 한다. 404/410은 무시한다.

**반복 규칙 값 약속(2026-10-21):** 편집 값 `v["recurrence"]`는 `model.KEEP`(None)=규칙 그대로, `model.NO_REPEAT`("")=반복 안 함,
`"RRULE:…"`=새 규칙. 새 코드에서는 None·"" 대신 이 이름을 쓴다.
'이번과 이후': 첫 회차면 전체로 처리한다. 앞쪽 자르기가 거절(4xx)되면 만든 뒤쪽을 지운다.
`Event.values()`는 `None`을 준다. 일정 창도 반복 칸을 손대지 않으면 `None`이고, 직접 고쳤을 때만 `""`나 규칙을 넣는다.
반복 규칙을 못 불러오면 일정 창을 열지 않는다(모르는 규칙을 '반복 안 함'으로 저장하지 않게).
'이번과 이후'는 뒤쪽 반복을 먼저 만들고(미리 정한 id) 앞쪽을 나중에 자른다. 그래야 다시 보내도 안전하다.
'이번과 이후'·'전체'로 나누는 기준은 회차의 원래 자리(`Event.original`/`slot`, 구글 originalStartTime)다. 다른 날로 옮긴 회차도 원래 자리로 자른다.
'전체'·'이후'로 고칠 때 완료·글자색 같은 속성은 이 회차에서 바꾼 것만 원본에 얹는다(`_series_values`).
규칙을 그대로 둔 '이후'는 예전 뒤쪽 회차 중 지운 것을 EXDATE로, 완료·글자색·옮긴 날짜를 새 회차에 다시 둔다(앞뒤 2년 안만).
보낼 편지함 작업에는 `"v": 2`가 붙는다. 표시가 없는 예전 작업은 불러올 때 `upgrade_job`이 바꾼다.

**새 일정 id:** 보낼 편지함이 `create_event`·`apply_ops`의 새 일정에 id(uuid hex)를 미리 붙이고 임시 id와 바로 짝짓는다.
다시 보내도 409로 막혀 두 번 만들어지지 않는다. 할 일(Tasks)은 id를 정할 수 없어 해당 없음.
